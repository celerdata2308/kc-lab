CelerData
Internal MCPs Setup Guide

Your starting point for connecting AI to every system we use — Feishu, Google Docs, StarRocks, BYOC Admin, and private clusters — all through Model Context Protocol.

01 — Overview

Why This Guide Exists

This is a recommended setup guide to help you connect Claude to CelerData's internal systems through MCP (Model Context Protocol) servers. Think of it as a starting point — the five servers below cover our most common workflows today, but the MCP library will keep growing as we connect more tools and build toward a fully AI-driven engineering experience.
Pick what you need and skip what you don't. Remote MCPs run on Railway with zero local setup; local MCPs run on your machine and need a bit more configuration.
MCP Server Type Description Prerequisites
feishu-mcp Remote Feishu/Lark docs, wiki, chat, messaging None
google-docs Remote Google Docs, Sheets, Drive None
starrocks Remote Shared StarRocks clusters Bearer token
byoc-admin Local BYOC cluster management & diagnostics Session cookie
starrocks-private Local Private metrics-pipeline cluster VPN + SSH tunnel
02 — Configuration

Config File

All MCP servers are defined in a single config file, aliased to the Claude Desktop config directory.

path 
# Source (edit here)
~/Documents/development/celerdata/claude_desktop_config.json

# Alias target (Claude Desktop reads from here)
~/Library/Application Support/Claude/claude_desktop_config.json
03 — Remote MCPs

Cloud-Hosted Servers

These run on Railway. No local setup required — just add the config and restart Claude Desktop.

📑

feishu-mcp Remote

Connects Claude to Feishu/Lark for searching and reading documents, wiki pages, chat messages, and sending messages.

claude_desktop_config.json 
"feishu-mcp": {
  "command": "npx",
  "args": [
    "mcp-remote",
    "https://feishu-mcp-production.up.railway.app/sse"
  ]
}

Tools: Search docs · Read wiki · List/read chats · Send messages · Export documents

📝

google-docs Remote

Connects Claude to Google Docs, Sheets, and Drive for reading, creating, and editing documents and spreadsheets. OAuth handled by the remote server.

claude_desktop_config.json 
"google-docs": {
  "command": "npx",
  "args": [
    "mcp-remote",
    "https://google-docs-mcp-production-b4cc.up.railway.app/sse"
  ]
}

Tools: Read/write/create Docs · Read/write Sheets · Drive files · Comments · Formatting

⚡

starrocks Remote

Connects Claude to shared StarRocks clusters for SQL queries, database exploration, and data visualization. Managed by the team — contact admin for a Bearer token.

claude_desktop_config.json 
"starrocks": {
  "command": "npx",
  "args": [
    "mcp-remote",
    "https://romantic-rebirth-production.up.railway.app/mcp",
    "--header",
    "Authorization:Bearer <your-token>"
  ]
}

Tools: list_clusters · use_cluster · read_query · write_query · db_summary · query_and_plotly_chart

04 — Local MCPs

Self-Hosted Servers

These run locally on your machine and require some setup.

🛠

byoc-admin Local

Connects Claude to the CelerData BYOC Admin API for cluster management, diagnostics, metrics, log search, and node-level commands.

1

Build the project

bash
cd ~/Documents/development/celerdata/byoc-admin-mcp
npm install
npm run build
2

Get your session cookie

Go to byoc-admin.celerdata.com → DevTools → Cookies → copy SRSAASSESSION

3

Add to config

claude_desktop_config.json
"byoc-admin": {
  "command": "node",
  "args": [
    "/Users/<you>/Documents/development/celerdata/byoc-admin-mcp/dist/index.js"
  ],
  "env": {
    "BYOC_COOKIE": "<your-SRSAASSESSION-cookie>"
  }
}

⚠️ Session cookie expires periodically. Refresh from browser if tools fail with auth errors.

05 — Private Cluster

starrocks-private

Connect Claude directly to the private-metrics-pipeline StarRocks cluster via SSH tunnel through a VPN-connected jump server.

Prerequisites

🔒
Proton VPN

Must be connected to reach the jump server

🔑
SSH Key

~/.ssh/byoc-user

🐍
Python uv/uvx

Install: brew install uv

One-Time Setup

1

Install uv

bash
brew install uv
2

Place the SSH key

bash
cp ~/Documents/development/celerdata/secrets/byoc-user ~/.ssh/byoc-user
chmod 600 ~/.ssh/byoc-user

⚠️ Must be in ~/.ssh/ — macOS blocks LaunchAgents from reading ~/Documents/

3

Install the LaunchAgent

bash
cp ~/Documents/development/celerdata/secrets/com.celerdata.sr-tunnel.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.celerdata.sr-tunnel.plist
4

Add the shell alias

bash
echo 'alias sr-tunnel="~/Documents/development/celerdata/secrets/sr-tunnel.sh"' >> ~/.zshrc
source ~/.zshrc
5

Add MCP config

claude_desktop_config.json
"starrocks-private": {
  "command": "uvx",
  "args": ["mcp-server-starrocks"],
  "env": {
    "STARROCKS_HOST": "127.0.0.1",
    "STARROCKS_PORT": "9030",
    "STARROCKS_USER": "<your-user>",
    "STARROCKS_PASSWORD": "<your-password>"
  }
}
6

Restart Claude Desktop

Daily Usage

Three commands. That's it.

terminal
# 1. Connect Proton VPN

# 2. Start the tunnel
sr-tunnel              # ✅ Tunnel connected! (localhost:9030)

# 3. Use Claude — it will query the cluster automatically

# When done:
sr-tunnel stop         # 🔌 Tunnel stopped

# Check status anytime:
sr-tunnel status       # ✅ Tunnel is running

Manual SSH Tunnel (without sr-tunnel)

bash
ssh -i ~/.ssh/byoc-user \
    -L 9030:1cogri9tn-internal.cloud-app.celerdata.com:9030 \
    -N \
    ec2-user@52.40.248.112

Troubleshooting

ProblemSolution
sr-tunnel fails Check Proton VPN is connected
launchctl: "Operation not permitted" SSH key must be in ~/.ssh/, not ~/Documents/ (macOS privacy restriction)
"Can't connect to MySQL server" Tunnel is not running — run sr-tunnel first
Works in Desktop, not in Cowork Cowork sandbox can't access localhost tunnel; use Claude Desktop (non-Cowork)
